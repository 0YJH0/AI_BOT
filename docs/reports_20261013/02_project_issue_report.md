# 项目问题报告与排障手册

基于 Isaac Lab 的机器人操作仿真、数据生成与策略评测

报告日期：2026-10-13。范围包括训练、数据、通信、初始化、相机、动作执行、评测和发布。问题来自保存的代码、状态文件、实验日志及历史复盘；没有定位到根因的条目明确标记为待定位。

## 1. 状态定义与处理原则

- 已修复：存在针对性代码，并有相关测试或完成记录支持。
- 已绕过：替代路径已工作，但原始故障根因尚未解决。
- 待验证：有假设或实现分支，尚无足够的对照证据。
- 待改进：当前功能可运行，但泛化、易用性或统计结论仍不足。

P0表示阻断当前运行或污染评测；P1表示影响准确性、复现性或跨机器使用；P2表示诊断与使用体验。所有“解决”都限定到当前软件版本和实验范围，不代表通用保证。

## 3. 通信问题

### COMM-01：端口占用

**现象。** 历史闭环对照状态曾记录：“通常每个套接字地址(协议/网络地址/端口)只允许使用一次”。这发生在监听服务建立阶段，不是模型推理质量问题。

**定位与处理。** 先查指定端口的监听PID，确认是否为本实验遗留服务，不要批量结束所有Python进程。新批量脚本用 `TcpListener(Loopback,0)` 选择空闲端口，把同一端口传给仿真客户端和模型服务器，并保存 `processes.json`。

**剩余风险。** 释放探测端口到正式监听之间仍有很短的竞争窗口。若要求生产级可靠性，应采用服务端原子绑定随机端口、写就绪文件再通知客户端的协议。当前实现不应被描述为完全消除端口竞争。

### COMM-02：就绪、超时和进程退出

**处理链路。** 模型日志出现 `SMOLVLA_SERVER_READY` 后才启动客户端；启动等待与单次RPC均有超时。标准库socket采用长度前缀分帧，`_receive_exact` 处理一次recv不能保证收满消息的问题；消息长度设上限，NumPy读取禁用pickle。

**故障处理。** `--require-vla` 将RPC异常向上抛出；`--pure-vla` 禁止专家动作兜底，以免“模型失败、专家完成”被记成VLA成功。脚本的finally只清理自己启动的子进程。通信异常应单列为基础设施失败，不应合并到策略抓取失败率中。

**不能做的推断。** CPU推理慢不自动意味着600控制步测试会超时。同步执行会等待推理，墙钟变慢与仿真时间变慢需要分开；真正的RPC超时、进程退出或步数耗尽要分别看日志。最新四组完整运行没有RPC中断，但未证明所有历史失败都与通信无关。

### COMM-03：批量环境路由

请求为 RGB `[B,H,W,3]`、状态 `[B,D]`、任务字符串列表和唯一环境ID；响应为动作 `[B,Horizon,8]` 与相同ID。客户端核对ID顺序，验证维度及有限数值。每个环境维护独立夹爪锁存、视觉窗口和动作目标，避免一个环境的结束或闭合影响其他环境。

**验证证据。** `tests/test_vla_batch_rpc.py` 与 `tests/test_vla_batch_execution.py` 覆盖编码、重复ID、行数不匹配、单次批量forward、动作顺序与保持语义。单测通过不代替真实相机重置测试；本次另外完成了16环境两轮容量验收与256回合对照。

## 4. 初始化和环境问题

### INIT-01：权重目录错误与配置缺失

**历史现象。** `config.json not found` 后，配置解析器报期望带 `type` 键的字典而得到空字典。另一类问题是路径缺少 `checkpoints` 层。首条错误才是排障入口，不应只修最后的解析异常。

**检查顺序。** 核对真实目录、步数补零、`config.json`、`adapter_config.json`、`adapter_model.safetensors` 和预处理/反归一化文件。检查状态维度、动作维度、chunk长度和基础模型路径。不要把缺失文件替换成空JSON，也不要只复制LoRA权重而遗漏归一化统计。

**当前措施。** `checkpoint.py` 负责策略配置加载；训练/评测脚本在启动前校验接口，权重哈希在运行前后比对。跨机器复制时仍须处理adapter配置中的基础模型绝对路径。

### INIT-02：依赖和警告

实测仿真环境为Isaac Sim 5.1.0、Isaac Lab 2.3.2、Torch 2.7.0+cu128；VLA环境为LeRobot0.4.4、PEFT0.18.1、Torch2.11.0+cu128、Transformers4.57.6。它们通过进程隔离协作，不应强行统一Torch版本。

`requirements-vla.txt` 声明的是另一条较新LeRobot版本范围，不是本次Windows实验的锁定文件。HDF5固定版本是为了避免GUI插件DLL冲突。PyAV解码回退警告通常不等于失败；判断以退出码、traceback和产物为准。

### INIT-03：远程USD资产

16环境TiledCamera扫描第一次曾在Franka资产加载阶段报USD找不到。该轮尚未形成完整工作负载，其启动期显存不能用于推断16环境容量。资产地址恢复可访问后补跑进入场景，随后暴露的是黑帧问题，二者不能合并成“显存不足”。

**建议流程。** 先验证网络和资产访问，再运行单环境场景；首次下载与缓存耗时单独记录。未来可提供资产缓存准备说明和网络预检，但不把NVIDIA资产重新打包为本项目自有资源。

## 5. 相机问题

### CAM-01：初始化窗口

读到RGB张量并不保证其中包含有效场景。当前并行测试检查标准差、像素跨度、有限正深度比例、视觉位姿有效性和连续稳定窗口，且窗口按环境隔离。相机位姿减去环境原点后的误差也要满足阈值。

**仍需注意。** 帧号递增只是软件传感器更新记录，不是GPU像素生成正确的证明；深度中存在有限值也不是完整标定正确的证明。应保留初始PNG与诊断JSON供人工核对。

### CAM-02：TiledCamera全黑

**已确认事实。** 4环境曾短测通过，但重跑中RGB标准差全为0；等待约180秒、1713个更新步仍然无效。普通相机同配置4路约2.83秒通过，16路也完成真实闭环。16环境普通相机容量测试峰值7631 MiB，仍有557 MiB余量。

**当前状态：绕过，不是根因修复。** 正式四组实验统一改用普通Camera，保留一个共享VLA模型和批量forward。相机输出方式改变没有取消物理并行，也没有把不同环境图像作为同一机器人的多视角输入。

**后续诊断方案。** 单独运行相机而不加载VLA；保存拼块前/后的原始RGB缓冲；逐项比较位姿写入、渲染设置、缓冲读取与拆分；每次只改一个因素，并与普通相机做一致性对照。不能仅凭黑帧就判断GPU算力不足，也不能未经定位直接认定是驱动或NVIDIA bug。

## 6. 控制、数据和训练问题

### CTRL-01：动作语义与提前闭合

当前动作标签为 `Δxyz + 目标四元数wxyz + 夹爪`，并非直接关节目标。动作开始时才将delta加到实时末端，之后保持5个控制步。夹爪安全门控使用视觉目标距离，并带锁存；它不等于真实接触力传感器。

“首次闭合距离”是第一次过滤后闭合指令发出时的距离，不证明手指此时已经夹到物体。最新报告用真值计算该指标；控制仍用视觉估计。`early_close_requests_over_2_5cm` 是在真值距离大于2.5 cm时输出闭合请求的累计动作数，不是独立闭合事件数，也不是碰撞次数。

### DATA-01：旧数据与新数据

历史数据存在接口和采样阶段迭代，不能笼统称所有旧数据都坏，也不能因为loss降低就认定其标签正确。新v9真值教师完整示范共600条成功轨迹、610次尝试，按episode划分为510/45/45条。训练标签来自执行链，不把目标真值作为学生输入；离线存储真值用于审计不等于模型消费真值。

### TRAIN-01：step、epoch和恢复配置

优化器step是参数更新次数，epoch是对数据集的完整遍历。估算等效epoch时，需要训练帧数、每次更新的有效batch大小、梯度累积和采样方式；加权有放回采样时，即使样本总量等效一遍，也不代表每帧都被访问。

当前v9导出训练帧为27338，因此不能脱离实际batch设置说6000step必然等于某个固定epoch。更不能把“6000个checkpoint编号”写为“6000个epoch”。历史PPO还修复过恢复BC优化器覆盖预期学习率的问题，训练摘要现在记录effective optimizer learning rate。

## 7. 评测问题与优先级

### EVAL-01：10 cm口径不一致

历史PPO报告检查 `z_object >= z_table + 0.10`；最新VLA额外检查 `z_object - z_initial >= 0.10`。方块初始中心已高于桌面，因此两者不是同一个约束。现有报告保留各自结果，不追溯篡改成功率；下一轮统一复测后才能得到严格同口径对比。

**验收建议。** 在统一评测器中保存初始物体高度、桌面高度、最大绝对高度、最大相对抬升、持续保持步数及失败原因。协议必须有版本，不能仅用“正式10 cm”这个自然语言短语代替实现细节。

### EVAL-02：超时不是根因

最新四组失败均记录为 `max_steps`。最佳组14/64成功，49/64最大抬升不到2 cm，但这不能自动推出“已经抓住而没有向上动作”。可能包括未对齐、空抓、阶段停滞、抓后滑落等不同路径。

下一步应通过原始动作Z、夹爪请求/过滤值、手指宽度、末端-物体距离、阶段切换和物体高度联合归因。先用这些证据选择恢复数据或阶段损失，再决定是否扩大LoRA秩或训练预算。

## 8. 运行与发布问题

### OPS-01：输出停住

`Get-Content ... -Wait` 只监听一个文件，文件停止增长后仍会等待。第一组日志不会自动跳到下一组。应先查看总 `pipeline_status.json` 的 `current_arm` 与 `stage`；若为COMPLETE且相关进程已退出，按Ctrl+C只会结束日志等待。

### RELEASE-01：社区复现边界

部分PowerShell脚本硬编码作者Conda路径。现有权重的基础模型路径也可能是本机绝对路径。仓库忽略了大部分 `results/` 和 `dataset/`，因此“克隆仓库”不等于“已经获得训练权重和数据”。当前未看到根目录授权许可证，不能擅自声明代码已按MIT等许可发布。

Demo README提供无需自训练权重的Scripted IK起点、带权重的视觉/VLA入口、依赖清单与缺失资源提示。正式开源前还应补：代码许可、模型许可、权重下载与哈希、无绝对路径启动器、全新机器验收记录。

## 9. 排障顺序与验收清单

1. 判定是训练、推理、仿真、渲染还是日志查看阶段；先看第一条真实异常。
2. 检查进程和端口，不随意结束其他项目的Python。
3. 验证权重目录、处理器、基础模型路径与接口维度。
4. 先运行单环境和独立RPC，再增加环境数。
5. 验证相机有效帧、坐标系和初始状态；失败则拒绝进入策略统计。
6. 对照动作标签、反归一化、delta锚点、执行保持和安全过滤。
7. 最后分析策略失败；保持相同种子、场景manifest、权重和指标定义。
8. 保存失败证据及状态，不通过删除异常回合来提高成功率。

本报告未新启动训练或仿真，也未声称上述待验证项已经完成。依据文件见 `01_project_challenges.md` 的E1-E9及同目录 `evidence_snapshot.json`；最新实验位于 `results/vla/medium64_parallel16_20261013_160323_916/`。
